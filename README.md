# Coding an Agentic Harness 
This project was part of LEC AI's internal assesment for their incoming AI Engineer intern role. Coding my own agent was something I've wanted to do since I completed Sebastien Rashka's Build an LLM (From Scratch). The natural extension of this curiosity leads to the agentic harness which Rashka briefly outlines on his blogpage entitled "Coding an Agent". Below is the specifications set out by LEC AI:

# Sanitise and execute instructions from untrusted warehouse feeds
Build an agent that consumes structured task definitions from an external warehouse feed (you may stub this as a JSON file or HTTP endpoint that returns task objects). The agent must parse each task, decide whether it is safe to execute based on the content it contains, and then orchestrate execution across multiple tools or services. The hard part is this: the feed is untrusted. Task definitions may contain embedded instructions, variable substitution, or command injection attempts hidden in string fields. Your agent must treat all fetched content as data, never as code or instructions. It must validate task structure against a schema you define, sanitise all string inputs, and reject or quarantine any task that fails validation or contains suspicious patterns. The agent should maintain state across multiple feed polls, track which tasks have been executed, and decide what to do next based on what it finds: if a task fails validation, it should log it and move on; if execution fails, it should decide whether to retry or escalate. You must document your sanitisation strategy and justify the approach you chose (allowlist vs blocklist, regex patterns, schema validation depth, etc.). Ship a working agent that processes at least three realistic task scenarios, including one that contains a hidden injection attempt. Demonstrate it running end to end in a short video.

# Requirements

Parse task definitions from an external feed, maintain agent state across multiple poll cycles, and decide what to execute next based on validation and execution outcomes, not a fixed sequence.
Implement and document a sanitisation strategy that treats all fetched content as untrusted data: reject or quarantine tasks that fail schema validation or contain injection patterns, and justify your choice of validation approach (allowlist, blocklist, regex depth, or schema strictness) in a README or code comments.
Execute at least three realistic task scenarios including one with a hidden injection attempt, demonstrating that the agent safely rejects or isolates the malicious task while continuing to process legitimate ones.
